# Dukenim Marketing — брифинг для Codex

Этот файл — полный ввод в курс дела для того, кто (или что) будет вести маркетинг Dukenim в Instagram/TikTok дальше. Раньше эту работу вёл Claude в отдельной сессии; теперь её продолжает Codex. Всё, что здесь написано, уже сделано или решено — не нужно передумывать заново, если не появится новая причина.

## 1. Разграничение зон

Это **отдельная работа от разработки продукта**, даже если её теперь тоже ведёт Codex. Правило прежнее: всё, что касается маркетинга/контента, живёт в папке `marketing/` этого репозитория (`yera47/DUKENIM`, приватный). Не путать маркетинговые задачи с задачами по коду приложения — это разные контексты, даже если инструмент один.

Источник правды по проекту — **`marketing/CLAUDE.md`**. Прочитать его первым делом, он длиннее и подробнее этого файла в частностях (правила публикации, статус доступа к API и т.д.) и должен обновляться при любых новых решениях.

## 2. Продукт: что такое Dukenim

Мультитенантная платформа: каждый магазин получает витрину-сайт под своим брендом, владелец управляет товарами/заказами из кабинета на телефоне. Технически — Next.js 15 + Supabase, витрина и кабинет читают одну и ту же базу (правки в кабинете сразу видны на витрине). Три роли: покупатель, владелец магазина, супер-админ.

**Важно для маркетинга:** технически это сайт-платформа, но **в коммуникации слово "сайт" не используется как ценность** — см. позиционирование ниже. Это сознательное решение, не забыть его при написании любого текста.

## 3. Целевая аудитория

Владельцы/продавцы малого бизнеса, которые **сейчас продают через Instagram-директ** без нормальной витрины: одежда, обувь, косметика, украшения, детские товары, спорттовары, домашний текстиль, подарки/сувениры, цветы, кондитерские/торты на заказ, мебель, зоотовары, автозапчасти, стройматериалы. Основные города — Казахстан, в первую очередь Алматы/Астана/Шымкент (см. раздел 7).

## 4. Позиционирование и УТП — не отклоняться

> **«Instagram — это лента. Dukenim — это каталог, который продаёт сам.»**

Логика: "сайт" — товар, который может сделать кто угодно на конструкторе, это не отличает нас от конкурентов. Ценность — **каталог**, который заменяет бесконечную ленту постов: клиент видит все товары сразу и заказывает сам, без переписки в директе.

Тон — уверенный, «операционная система для бизнеса» (в духе того, как Apple/Google/Microsoft говорят о своих платформах), но **адаптированный под казахстанский рынок**, не калька — свой характер, не корпоративный американский тон.

Проверочный вопрос перед публикацией любого текста: **есть ли там слово "сайт" как продающий аргумент?** Если да — переписать через "каталог".

## 5. Бренд-система (утверждённый брендбук v1.0, август 2026 — ПОСЛЕ gold-обновления)

Источник: `Dukenim_Brandbook_2026.pdf` (актуальный) в корне репозитория `DUKENIM`. **Важно:** в середине проекта был ребрендинг цвета — зелёный акцент заменён на золотой. Файл с суффиксом `_before_gold_update` устарел, не использовать. Если где-то встретится `#2F8F68`/`#06271F` (старый зелёный) — это ошибка, поправить на актуальное ниже.

- **Тэглайн:** «Одна дверь. Вся система бизнеса.» Знак D = дверь + начало пути бизнеса.
- **Три опоры:** Понятно (сложное → простое) / Системно (все каналы как одно целое) / Своё (характер Казахстана, не калька).
- **Цвета:** Black Jade `#071B17` (доминирующий, ~55%), Aged Gold `#B08A50` (акцент — «порог» и точка в логотипе, ~15%), Pale Stone `#F4F0E8` (светлый фон, ~25%), Graphite `#101713`, Warm Sand `#E8DFD0` (~5%).
- **Шрифт:** Manrope (заголовки ExtraBold, текст Regular, кнопки Bold). Arial — только системная замена, не для контента.
- **Логотип:** `marketing/brand-assets/dukenim-flat-master.png` (полная версия, светлый фон), `-reversed.png` (тёмный фон), `-gold.png`, `dukenim-flat-symbol*.png` (только знак D — для аватаров/мелких форматов). Порог и точка — всегда золотые, точку нельзя убирать. Нельзя растягивать, менять цвета, добавлять эффекты, класть на шумный фон, поворачивать.
- **Готовый Instagram-аватар:** `marketing/brand-assets/dukenim-instagram-d-flat-1080.png` — использовать как есть.

## 7. Рыночное исследование — уже готово

`marketing/research/` содержит точные числа организаций из 2ГИС (org_count, серверный расчёт, без ручной дедупликации) по 15 городам Казахстана × 14 товарным категориям:

- `dukenim_2gis_raw_counts.csv` — полная таблица город × категория
- `dukenim_2gis_city_ranking.csv` — города, ранжированные по общему числу организаций
- `dukenim_main_cities.csv` — топ-5 городов (Алматы, Астана, Шымкент, Караганда, Ақтау) детально

**Ключевые цифры:** топ-5 городов = 57 899 организаций, все 15 городов = 91 200. Лидирующая категория — одежда (24 854, 27%), затем детские товары (12 787), мебель (8 433). Топ-3 города (Алматы/Астана/Шымкент) = 52% всего рынка.

**Не завершено:** вычет известных сетей (H&M, Zara, Спортмастер и т.д.) и точек, у которых уже есть свой сайт — для этого нужен эндпоинт `/3.0/items` API 2ГИС, который на момент составления этого файла возвращает `apiKeyIsBlocked` (заблокирован после ~9000 запросов за час — вероятно, антиабуз-лимит). Справочник категорий `/2.0/catalog/*` при этом работает — блокировка точечная, не на весь ключ. Нужно написать на api@2gis.ru с уточнением именно этого. Ключ (если понадобится) искать в истории обращений с пользователем — сюда открыто не вставляю по соображениям безопасности.

## 9. Какие ИИ/API использовать и зачем

| Инструмент | Роль | Статус | Стоимость |
|---|---|---|---|
| **Видео-генерация: Kling** | Генерация Reels/TikTok-роликов из сценариев | Выбран как самый дешёвый рабочий API, **не протестирован** — начать с 5-10 брифов и посчитать реальный чек, прежде чем масштабировать | ~$0.18–0.31 за 5-сек ролик (API) |
| **Meta Graph API** (Instagram Business) | Публикация постов/Reels программно | Не настроено — нужен Business/Creator аккаунт, подключённый к Facebook-странице, Meta App с правом `instagram_content_publish`, долгоживущий токен, Instagram Business Account ID | Бесплатно, только время на настройку |
| **2GIS Catalog API** | Рыночные данные для калибровки модели охвата | Ключ частично заблокирован (см. раздел 7) | Уточняется у 2ГИС |
| **Веб-поиск/браузер** | trend-research — тренды форматов/звуков | Обычный поиск и просмотр как пользователь, **без автоматизированного скрапинга через неофициальные API** — это против ToS Meta/TikTok и грозит баном | — |

**Почему Kling, а не Runway/Veo/Pika:** сравнивали по цене API (Kling дешевле всех рабочих вариантов, ~$0.18-0.31 за ролик против $0.25-0.60 у Runway), с учётом что ни у одного провайдера нет по-настоящему бесплатного продакшн-уровня API. Если Codex хочет пересмотреть выбор — сначала протестировать альтернативу на том же наборе брифов и сравнить реальную стоимость+качество, не менять вслепую.

**Почему не несколько видео-провайдеров одновременно:** явное решение пользователя — один провайдер, протестировать, посчитать себестоимость, потом при необходимости пересмотреть. Несколько провайдеров = сложнее поддерживать, сравнивать результат, экономии почти нет (у всех pay-per-second/per-clip модель).

## 11. Жёсткие правила — не нарушать ни при каких обстоятельствах

Это не пожелания, это прямые указания пользователя из истории проекта:

1. **Ни один ролик не публикуется автоматически без явного одобрения пользователя.** Автопостинг разрешён только для уже одобренных материалов по расписанию.
2. **Никогда не логиниться в Instagram/любой аккаунт пользователя напрямую** (логин/пароль) — это входит в список действий, запрещённых в принципе, независимо от степени желаемой автоматизации.
3. **Не тратить деньги на генерацию видео без явного согласия** на конкретный бриф/пакет брифов.
4. **Не использовать автоматизированный скрапинг** Instagram/TikTok через неофициальные API — только обычный просмотр браузером и официальные API там, где они есть (Meta Graph API, 2ГИС).
5. **Никогда не говорить "сайт" как ценность продукта** в маркетинговых текстах — см. раздел 4.
6. Контент-план (`content-calendar`) всегда идёт **на утверждение пользователю до производства** — не переходить к сценариям/видео по неутверждённым идеям.
